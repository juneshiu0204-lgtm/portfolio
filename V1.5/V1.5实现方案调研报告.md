## 一、缓冲区分析（Buffer Analysis）

### 1.1 功能说明

缓冲区分析是GIS中最常用的空间操作之一，用于围绕点、线、面要素生成一定距离内的影响区域。典型应用场景包括：

- 地铁站周边500米生活圈分析
- 高速公路噪声影响带
- 河流生态保护区划定
- 环境影响评估

### 1.2 开源实现方案

#### 方案一：GDAL/OGR（推荐）

**技术栈**：Python + GDAL/OGR

**实现方式**：

```python
from osgeo import ogr

def buffer_analysis(input_shp, output_shp, distance):
    driver = ogr.GetDriverByName('ESRI Shapefile')
    dataSource = driver.Open(input_shp, 0)
    layer = dataSource.GetLayer()
    
    outDriver = ogr.GetDriverByName('ESRI Shapefile')
    outDataSource = outDriver.CreateDataSource(output_shp)
    outLayer = outDataSource.CreateLayer('buffer', geom_type=ogr.wkbPolygon)
    
    for feature in layer:
        geom = feature.GetGeometryRef()
        buffer_geom = geom.Buffer(distance)
        outFeature = ogr.Feature(outLayer.GetLayerDefn())
        outFeature.SetGeometry(buffer_geom)
        outLayer.CreateFeature(outFeature)
```

**优势**：

- GDAL 3.12+ 版本提供 `gdal vector buffer` 命令行工具
- 支持多种数据格式（Shapefile、GeoJSON、PostGIS等）
- 性能优秀，底层C++实现
- 支持负距离（收缩几何体）
- 可配置缓冲区精度和样式参数

**劣势**：

- 需要安装GDAL库（约200MB）
- Python绑定需要编译或使用预编译包

**参考文档**：

- [GDAL Vector Buffer](https://gdal.org/en/stable/programs/gdal_vector_buffer.html)
- [GDAL Python Vector API](https://gdal.org/api/python/vector_api.html)

## 二、叠加分析（Overlay Analysis）

### 2.1 功能说明

叠加分析是对两个或多个图层进行空间运算，生成新的空间要素。主要包括：

- **相交（Intersection）**：提取两个图层的重叠部分
- **联合（Union）**：合并两个图层的所有区域
- **差分（Difference）**：从一个图层中减去另一个图层
- **对称差分（SymDifference）**：提取两个图层不重叠的部分

典型应用场景：

- 土地利用变化分析
- 规划选址分析
- 生态敏感性评价
- 多因子叠加分析

## 三、空间插值（Spatial Interpolation）

### 3.1 功能说明

空间插值是根据已知点的属性值，推测未知点属性值的方法。主要包括：

- **反距离权重插值（IDW）**：基于距离的反比加权
- **克里金插值（Kriging）**：基于统计学的最优插值
- **样条函数插值（Spline）**：基于平滑曲面拟合
- **自然邻域插值（Natural Neighbor）**：基于Voronoi图

典型应用场景：

- 气象数据插值（温度、降水等）
- 土壤属性插值
- 地形高程插值
- 污染物浓度分布

### 3.2 开源实现方案

#### 方案一：GDAL Grid（推荐）

**技术栈**：Python + GDAL

**实现方式**：

```python
from osgeo import gdal

# 使用gdal_grid命令行工具
gdal.Grid(
    'output.tif',
    'input.vrt',
    format='GTiff',
    outputBounds=[xmin, ymin, xmax, ymax],
    width=1000,
    height=1000,
    algorithm='invdist:power=2.0:smoothing=0.0',  # IDW
    # algorithm='linear',  # 线性插值
    # algorithm='nearest',  # 最近邻插值
)
```

**GDAL命令行工具**：

```bash
gdal_grid -a invdist:power=2.0:smoothing=0.0 \
  -txe xmin xmax -tye ymin ymax \
  -outsize 1000 1000 \
  -of GTiff \
  -l points input.vrt output.tif
```

**支持的插值方法**：

1. **invdist**：反距离权重插值（IDW）
   - 参数：power（权重幂次）、smoothing（平滑参数）、radius（搜索半径）
2. **linear**：线性插值（基于Delaunay三角剖分）
3. **nearest**：最近邻插值
4. **average**：平均值插值

**优势**：

- GDAL原生支持，无需额外依赖
- 性能优秀，C++底层实现
- 支持多种插值方法
- 支持大数据量处理
- 输出标准GeoTIFF格式

**劣势**：

- 不支持克里金插值（Kriging）
- 配置相对复杂

**参考文档**：

- [GDAL Grid Tutorial](https://gdal.org/tutorials/gdal_grid_tut.html)
- [gdal\_grid](https://gdal.org/en/stable/programs/gdal_grid.html)

#### 方案二：SciPy + GDAL

**技术栈**：Python + SciPy + GDAL

**实现方式**：

```python
from scipy.interpolate import griddata
import numpy as np
from osgeo import gdal

# 读取点数据
points = np.array([[x1, y1], [x2, y2], ...])
values = np.array([z1, z2, ...])

# 创建网格
grid_x, grid_y = np.mgrid[xmin:xmax:1000j, ymin:ymax:1000j]

# IDW插值（使用linear方法近似）
grid_z = griddata(points, values, (grid_x, grid_y), method='linear')

# 克里金插值需要使用其他库
from pykrige.ok import OrdinaryKriging
ok = OrdinaryKriging(points[:, 0], points[:, 1], values, 
                     variogram_model='linear')
z, ss = ok.execute('grid', grid_x, grid_y)
```

**优势**：

- SciPy提供多种插值方法
- 支持克里金插值（通过PyKrige库）
- 灵活性高，可自定义算法

**劣势**：

- 需要额外依赖（SciPy、PyKrige）
- 性能不如GDAL原生方法
- 需要手动处理空间参考

**参考文档**：

- [SciPy griddata](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.griddata.html)
- [PyKrige](https://github.com/GeoStat-Framework/PyKrige)

## 四、数据拼接与镶嵌（Mosaic & Merge）

### 4.1 功能说明

数据拼接与镶嵌是将多幅影像合并成一幅完整影像的处理过程，是遥感数据处理中的核心功能。

#### 4.1.1 数据拼接（Merge）

将多幅相邻或重叠的影像简单地拼接在一起，主要处理：

- 几何位置对齐
- 分辨率统一
- 数据范围合并
- NoData值处理

#### 4.1.2 数据镶嵌（Mosaic）

在拼接的基础上进行更高级的处理，包括：

- **镶嵌线自动提取**：在重叠区域寻找最优接缝线
- **色彩平衡**：消除不同影像间的色调差异
- **匀光处理**：平滑过渡区域的亮度差异
- **几何配准**：精确对齐重叠区域

典型应用场景：

- 大范围遥感影像制图
- 卫星影像无缝拼接
- 航拍影像正射纠正后镶嵌
- 多时相影像合成

### 4.2 开源实现方案

#### 方案一：GDAL gdal\_merge.py（推荐用于简单拼接）

**技术栈**：Python + GDAL

**实现方式**：

```python
import subprocess

# 命令行方式
subprocess.run([
    'gdal_merge.py',
    '-o', 'output.tif',
    '-of', 'GTiff',
    '-co', 'COMPRESS=LZW',
    '-ps', '10.0', '10.0',  # 输出分辨率
    '-n', '0',  # NoData值
    'image1.tif', 'image2.tif', 'image3.tif'
])

# Python API方式
from osgeo_utils.gdal_merge import gdal_merge

gdal_merge([
    '-o', 'output.tif',
    '-of', 'GTiff',
    'image1.tif', 'image2.tif'
])
```

**优势**：

- GDAL原生工具，稳定可靠
- 支持多种数据格式
- 支持不同分辨率的影像拼接
- 自动处理重叠区域（后一幅覆盖前一幅）
- 支持NoData值设置

**劣势**：

- 不支持自动色彩平衡
- 不支持镶嵌线自动提取
- 大数据量时内存占用较高
- 重叠区域处理简单（直接覆盖）

**参考文档**：

- [GDAL gdal\_merge](https://gdal.org/en/stable/programs/gdal_merge.html)

#### 方案二：GDAL gdalwarp（推荐用于高级镶嵌）

**技术栈**：Python + GDAL

**实现方式**：

```python
import subprocess

# 单次镶嵌
subprocess.run([
    'gdalwarp',
    'image1.tif', 'image2.tif',
    'output.tif',
    '-co', 'COMPRESS=LZW',
    '-cutline', 'cutline.shp',  # 可选：使用矢量裁剪线
    '-cblend', '30',  # 混合带宽（像素）
    '-dstnodata', '0'
])

# 多文件镶嵌
subprocess.run([
    'gdalwarp',
    '-overwrite',
    '-of', 'GTiff',
    '-co', 'COMPRESS=LZW',
    '-cutline', 'seamline.shp',
    '-cblend', '50',
    '*.tif',
    'mosaic.tif'
])
```

#### 4.3.1 镶嵌线自动提取

**技术方案**：基于图割（Graph Cut）或动态规划（Dynamic Programming）

**实现难度**：高

**开源工具**：

1. **OpenCV + Python**：实现图割算法
2. **GDAL + NumPy**：实现动态规划算法
3. **自定义算法**：基于梯度、纹理、道路网络等

**示例代码（简化版动态规划）**：

```python
import numpy as np
from osgeo import gdal

def find_seamline(img1, img2, overlap_region):
    """
    在重叠区域寻找最优镶嵌线
    基于梯度差异最小化原则
    """
    # 计算梯度差异
    diff = np.abs(img1 - img2)
    
    # 使用动态规划寻找最小代价路径
    rows, cols = diff.shape
    cost = np.zeros_like(diff)
    
    # 动态规划
    for i in range(1, rows):
        for j in range(1, cols-1):
            cost[i, j] = diff[i, j] + min(
                cost[i-1, j-1],
                cost[i-1, j],
                cost[i-1, j+1]
            )
    
    # 回溯找到最优路径
    seamline = []
    j = np.argmin(cost[-1, :])
    for i in range(rows-1, -1, -1):
        seamline.append((i, j))
        if i > 0:
            j = np.argmin(cost[i-1, max(0,j-1):min(cols,j+2)]) + max(0, j-1)
    
    return seamline
```

#### 4.3.2 色彩平衡（Color Balancing）

**技术方案**：直方图匹配、匀光处理、色彩归一化

**实现方式**：

```python
import numpy as np
from osgeo import gdal

def histogram_matching(source, reference):
    """
    直方图匹配：将源影像的直方图匹配到参考影像
    """
    # 计算直方图
    src_hist, bins = np.histogram(source.flatten(), 256, [0, 256])
    ref_hist, _ = np.histogram(reference.flatten(), 256, [0, 256])
    
    # 计算累积分布函数（CDF）
    src_cdf = src_hist.cumsum()
    ref_cdf = ref_hist.cumsum()
    
    # 归一化
    src_cdf = src_cdf / src_cdf[-1]
    ref_cdf = ref_cdf / ref_cdf[-1]
    
    # 映射
    lookup_table = np.interp(src_cdf, ref_cdf, np.arange(256))
    
    return lookup_table[source]

def dodging_correction(img, overlap_area):
    """
    匀光处理：在重叠区域进行亮度调整
    """
    # 计算重叠区域的均值和标准差
    mean_overlap = np.mean(img[overlap_area])
    std_overlap = np.std(img[overlap_area])
    
    # 全局调整
    mean_global = np.mean(img)
    std_global = np.std(img)
    
    # 线性变换
    corrected = (img - mean_global) / std_global * std_overlap + mean_overlap
    
    return corrected
```

**实现难度**：中等

**注意事项**：

- 色彩平衡可能改变影像的辐射特性
- 需要保留原始数据供专业分析使用
- 建议提供多种色彩平衡算法供用户选择

**2. 规则引擎实现**
```python
import re
import json
import psycopg2
from typing import List, Dict

class DataClassificationEngine:
    """
    数据分类规则引擎
    支持文件名正则匹配和元数据字段提取
    """
    
    def __init__(self, db_connection):
        self.db_conn = db_connection
    
    def load_rules(self):
        """
        加载所有启用的规则
        """
        cursor = self.db_conn.cursor()
        cursor.execute("""
            SELECT id, rule_name, rule_type, extraction_config, tag_key
            FROM classification_rules
            WHERE is_enabled = TRUE
            ORDER BY priority DESC, created_at ASC
        """)
        
        rules = []
        for row in cursor.fetchall():
            rules.append({
                'id': row[0],
                'name': row[1],
                'type': row[2],
                'config': row[3],
                'tag_key': row[4]
            })
        
        return rules
    
    def extract_by_regex(self, filename: str, config: dict) -> str:
        """
        通过正则表达式从文件名提取标签
        
        Args:
            filename: 文件名
            config: {
                "pattern": "正则表达式",
                "source": "filename",
                "group": 1  # 提取的分组
            }
        
        Returns:
            提取的标签值
        """
        pattern = config.get('pattern', '')
        group = config.get('group', 0)
        
        match = re.search(pattern, filename)
        if match:
            return match.group(group)
        
        return None
    
    def extract_by_metadata(self, metadata: dict, config: dict) -> str:
        """
        从元数据字段提取标签
        
        Args:
            metadata: 数据元信息
            config: {
                "field": "字段名",
                "mapping": {  # 值映射（可选）
                    ".tif": "遥感影像",
                    ".shp": "矢量数据"
                }
            }
            或
            config: {
                "field": "字段名",
                "ranges": [  # 范围映射（可选）
                    {"min": 0, "max": 0.5, "value": "高分辨率"},
                    {"min": 0.5, "max": 2.0, "value": "中分辨率"}
                ]
            }
        
        Returns:
            提取的标签值
        """
        field = config.get('field')
        field_value = metadata.get(field)
        
        if field_value is None:
            return None
        
        # 值映射
        if 'mapping' in config:
            mapping = config['mapping']
            return mapping.get(str(field_value))
        
        # 范围映射
        if 'ranges' in config:
            ranges = config['ranges']
            for range_config in ranges:
                min_val = range_config.get('min', float('-inf'))
                max_val = range_config.get('max', float('inf'))
                
                if min_val <= field_value < max_val:
                    return range_config.get('value')
        
        # 直接返回字段值
        return str(field_value)
    
    def classify_data(self, filename: str, metadata: dict) -> List[Dict]:
        """
        对数据进行分类打标
        
        Args:
            filename: 文件名
            metadata: 数据元信息
                {
                    'file_extension': '.tif',
                    'satellite': 'SV1-01',
                    'resolution': 0.5,
                    'acquisition_time': '2025-01-01',
                    ...
                }
        
        Returns:
            tags: 标签列表 [{'key': 'data_type', 'value': '遥感影像'}, ...]
        """
        rules = self.load_rules()
        tags = []
        
        for rule in rules:
            try:
                tag_value = None
                
                # 根据规则类型提取标签
                if rule['type'] == 'regex':
                    tag_value = self.extract_by_regex(filename, rule['config'])
                elif rule['type'] == 'metadata':
                    tag_value = self.extract_by_metadata(metadata, rule['config'])
                
                # 添加标签
                if tag_value:
                    tags.append({
                        'key': rule['tag_key'],
                        'value': tag_value,
                        'rule_id': rule['id']
                    })
            except Exception as e:
                print(f"规则执行失败: {rule['name']}, 错误: {e}")
                continue
        
        return tags
    
    def save_tags_to_metadata(self, data_id: int, tags: List[Dict]):
        """
        将标签保存到数据元数据的"资产标签"字段
        
        Args:
            data_id: 数据ID
            tags: 标签列表
        """
        cursor = self.db_conn.cursor()
        
        # 将标签转换为JSON格式
        asset_tags = {tag['key']: tag['value'] for tag in tags}
        
        # 更新元数据中的资产标签字段
        cursor.execute("""
            UPDATE data_metadata
            SET asset_tags = %s,
                updated_at = NOW()
            WHERE id = %s
        """, (json.dumps(asset_tags, ensure_ascii=False), data_id))
        
        self.db_conn.commit()
```

## 七、矢量瓦片服务（MVT）

### 7.1 功能说明

矢量瓦片（Vector Tiles）是一种高效的数据传输格式，将矢量数据按瓦片组织，支持：
- **MVT格式**：Mapbox Vector Tile标准格式
- **动态生成**：根据请求实时生成矢量瓦片
- **样式灵活**：客户端可自定义渲染样式
- **性能优秀**：数据量小，传输快

典型应用场景：
- 大规模矢量数据可视化
- 自定义样式地图
- 离线地图应用

### 7.2 开源实现方案

#### 方案一：PostGIS ST_AsMVT（推荐）

**技术栈**：PostgreSQL + PostGIS

**实现方式**：
```sql
-- 创建矢量瓦片生成函数
CREATE OR REPLACE FUNCTION get_mvt(z integer, x integer, y integer)
RETURNS bytea AS $$
DECLARE
    mvt bytea;
    bounds geometry;
BEGIN
    -- 计算瓦片范围
    bounds := ST_TileEnvelope(z, x, y);
    
    -- 生成MVT
    SELECT ST_AsMVT(tile, 'layer_name', 4096, 'geom')
    INTO mvt
    FROM (
        SELECT 
            id,
            name,
            ST_AsMVTGeom(
                geom,
                bounds,
                4096,
                256,
                true
            ) AS geom
        FROM my_table
        WHERE geom && bounds
    ) AS tile;
    
    RETURN mvt;
END;
$$ LANGUAGE plpgsql;

-- 查询矢量瓦片
SELECT get_mvt(10, 512, 384);
```

### 7.4 产品设计决策

经过需求讨论，确定以下设计决策：

#### 7.4.1 核心流程
```
shp/geojson文件
  → 入库PG（上传时直接入库 或 先存储后转入库）
  → 发布MVT服务（可选择绑定样式：1个默认 + N个可选）
  → 前端渲染（查询绑定关系获取样式，转换为 Mapbox Style 后渲染）
```

#### 7.4.2 样式体系说明

MVT 是客户端渲染，前端渲染库（MapLibre GL JS）使用 **Mapbox Style Spec（JSON格式）** 定义样式，与 WMS/WMTS 使用的 SLD（XML格式）不同。

**两套样式格式对比**：

| | SLD | Mapbox Style Spec |
|---|---|---|
| 格式 | XML | JSON |
| 渲染位置 | 服务端（GeoServer） | 客户端（MapLibre GL JS） |
| 适用服务 | WMS / WMTS | MVT |

**样式演进路线**：

- **V1.5（本期）**：通过 [GeoStyler](https://geostyler.org/) 将现有 SLD 自动转换为 Mapbox Style，复用现有样式资产。转换存在一定损耗，复杂符号化效果可能有偏差。
- **后续迭代**：新增 Mapbox Style JSON 原生编辑和管理能力，最终维护 SLD 和 Mapbox Style 两套样式体系，分别服务于不同服务类型。

#### 7.4.3 设计决策汇总

| 决策项 | 选择 | 说明 |
|--------|------|------|
| MVT样式格式 | Mapbox Style Spec（JSON） | MVT客户端渲染标准格式 |
| V1.5样式来源 | SLD → GeoStyler → Mapbox Style | 复用现有SLD资产，自动转换 |
| 样式绑定方式 | 发布时可选配置 | 1个默认样式 + N个可选样式 |
| 入库时机 | 上传时直接入库 或 先存储后转入库 | 两种方式可选 |
| 入库后处理 | 原文件可保留或删除 | 用户可选 |
| 数据管理 | 统一管理 | 通过格式筛选区分来源（shp/geojson/pg） |
| 前端样式应用 | 服务URL与样式绑定关系 | 现有逻辑复用，样式格式替换为Mapbox Style |

1. **Shapefile/GeoJSON入库PG**
   - 上传时直接入库
   - 先存储后转入库（可保留或删除原文件）

## 八、MBTiles多文件支持

### 8.1 功能说明

支持以下三种场景：
- **分区域制作后合并**：各区域分别生成 MBTiles，最终合并为一个完整文件
- **增量更新某个区域**：用新数据覆盖已有文件中特定区域的瓦片
- **多文件联合发布服务**：不合并，多个 MBTiles 文件作为一个服务对外提供

对应两个子功能：

| 子功能 | 说明 | 对应场景 |
|---|---|---|
| 多文件合并 | 物理合并，支持追加/覆盖两种冲突策略 | 分区域合并、增量更新 |
| 多文件联合发布 | 虚拟路由，多文件作为一个服务对外 | 多文件同时发布 |

### 8.2 子功能一：多文件合并

**技术栈**：Python + SQLite

MBTiles 本质是 SQLite 数据库，合并即将多个库的瓦片数据写入同一个库。支持两种冲突策略：
- **追加模式**：目标文件已有的瓦片保留，只补充缺失瓦片
- **覆盖模式**：新文件的瓦片覆盖目标文件中同位置的瓦片（用于增量更新）

**实现方式**：
```python
import sqlite3

def merge_mbtiles(output_file, input_files, mode='append'):
    """
    mode: 'append' 追加（已有瓦片保留） | 'replace' 覆盖（新瓦片优先）
    """
    conn_out = sqlite3.connect(output_file)
    cursor_out = conn_out.cursor()

    cursor_out.executescript('''
        CREATE TABLE IF NOT EXISTS map (
            zoom_level INTEGER,
            tile_column INTEGER,
            tile_row INTEGER,
            tile_id TEXT,
            PRIMARY KEY (zoom_level, tile_column, tile_row)
        );
        CREATE TABLE IF NOT EXISTS images (
            tile_id TEXT PRIMARY KEY,
            tile_data BLOB
        );
    ''')

    insert_sql = (
        'INSERT OR REPLACE INTO images VALUES (?, ?)'
        if mode == 'replace'
        else 'INSERT OR IGNORE INTO images VALUES (?, ?)'
    )
    map_sql = (
        'INSERT OR REPLACE INTO map VALUES (?, ?, ?, ?)'
        if mode == 'replace'
        else 'INSERT OR IGNORE INTO map VALUES (?, ?, ?, ?)'
    )

    for input_file in input_files:
        conn_in = sqlite3.connect(input_file)
        cursor_in = conn_in.cursor()
        cursor_in.execute('SELECT tile_id, tile_data FROM images')
        cursor_out.executemany(insert_sql, cursor_in.fetchall())
        cursor_in.execute('SELECT zoom_level, tile_column, tile_row, tile_id FROM map')
        cursor_out.executemany(map_sql, cursor_in.fetchall())
        conn_in.close()

    conn_out.commit()
    conn_out.close()
```

### 8.3 子功能二：多文件联合发布

**技术栈**：Python + SQLite + 路由层

不合并文件，服务端维护一张路由表，记录每个 MBTiles 的地理范围和层级。请求进来时按 z/x/y 查路由表，定位到对应文件后读取瓦片返回。

**核心流程**：
```
请求 GET /tiles/{z}/{x}/{y}
        ↓
   路由层：查哪个 MBTiles 覆盖了该 z/x/y
        ↓
   命中 beijing.mbtiles → 读取瓦片数据返回
   未命中任何文件 → 返回 204 No Content
```

**路由表结构**：
```json
[
  {
    "file": "beijing.mbtiles",
    "min_zoom": 0, "max_zoom": 18,
    "bounds": [115.4, 39.4, 117.5, 41.1],
    "priority": 1
  },
  {
    "file": "shanghai.mbtiles",
    "min_zoom": 0, "max_zoom": 18,
    "bounds": [120.8, 30.6, 122.0, 31.9],
    "priority": 1
  }
]
```

**路由查询实现**：
```python
import sqlite3
import json

class MBTilesRouter:
    def __init__(self, config_file):
        with open(config_file) as f:
            # 按优先级排序，priority 大的优先
            self.sources = sorted(json.load(f), key=lambda x: -x['priority'])

    def get_tile(self, z, x, y):
        for source in self.sources:
            if not (source['min_zoom'] <= z <= source['max_zoom']):
                continue
            # TMS 坐标转换（MBTiles 使用 TMS，y 轴与 XYZ 相反）
            tms_y = (1 << z) - 1 - y
            conn = sqlite3.connect(source['file'])
            row = conn.execute(
                'SELECT tile_data FROM tiles WHERE zoom_level=? AND tile_column=? AND tile_row=?',
                (z, x, tms_y)
            ).fetchone()
            conn.close()
            if row:
                return row[0]
        return None  # 返回 None 时响应 204
```

**需要处理的细节**：
- **重叠区域**：通过 `priority` 字段控制优先级，值大的文件优先
- **空瓦片**：所有文件均无该瓦片时返回 204，不报错
- **元数据合并**：联合发布时对外暴露的 `bounds`、`minzoom`、`maxzoom` 需合并所有文件的元数据计算得出

### 8.4 推荐方案

两个子功能均使用 Python + SQLite 自行实现，无需引入额外工具，与现有系统集成方便。

## 九、点云数据格式（.las/.laz）支持

### 9.1 功能说明

支持点云数据（.las/.laz）的汇聚入库、格式转换、服务发布和可视化预览，覆盖完整数据生命周期。

典型应用场景：
- 地形测量与DEM生成
- 城市三维建模
- 林业资源调查
- 电力线路巡检

### 9.2 LAS/LAZ 格式特点

- **LAS**：ASPRS 标准点云格式，存储 XYZ 坐标、强度、分类、RGB 等属性，二进制格式
- **LAZ**：LAS 的无损压缩版本，体积约为 LAS 的 10-20%，是实际生产中的主流格式
- 文件可达数 GB，单文件包含数亿个点，处理需考虑内存和性能

### 9.3 功能实现方案

#### 9.3.1 数据汇聚入库

**技术栈**：Python + PDAL + PostgreSQL

PDAL（Point Data Abstraction Library）是点云处理的标准开源库，支持 LAS/LAZ 读写及元数据提取。

**元数据提取**：
```python
import pdal
import json

def extract_las_metadata(file_path):
    pipeline = pdal.Pipeline(json.dumps({
        "pipeline": [{"type": "readers.las", "filename": file_path}]
    }))
    pipeline.execute()
    metadata = pipeline.metadata
    info = metadata['metadata']['readers.las'][0]
    return {
        "point_count":   info['count'],
        "crs":           info['srs']['wkt'],
        "bounds":        info['bounds'],   # [xmin, xmax, ymin, ymax, zmin, zmax]
        "las_version":   f"{info['major_version']}.{info['minor_version']}",
        "point_format":  info['dataformat_id'],
    }
```

**入库方式**：原始文件存储在文件系统，元数据写入数据库，不将点云数据写入 PG（数据量过大）。

#### 9.3.2 格式转换：LAZ → 3D Tiles（pnts）

Web 端无法直接加载 LAS/LAZ，需转换为 **3D Tiles** 格式（点云用 `.pnts` 瓦片），供 Cesium/前端流式加载。

**技术栈**：Python + py3dtiles 或 PDAL + Entwine

**方案一：py3dtiles（推荐，轻量）**
```bash
py3dtiles convert input.laz --out output_dir/
# 输出 tileset.json + 若干 .pnts 文件
```

**方案二：Entwine + EPT（适合超大数据量）**
```bash
# 生成 EPT（Entwine Point Tile）索引
entwine build -i input.laz -o ept_output/

# EPT 可直接被 Potree / Cesium 加载
```

| | py3dtiles | Entwine + EPT |
|---|---|---|
| 适用数据量 | 中小型（< 5亿点） | 超大型（数十亿点） |
| 输出格式 | 3D Tiles pnts | EPT（Potree/Cesium均支持） |
| 部署复杂度 | 低 | 中 |

#### 9.3.3 服务发布

转换后的 3D Tiles 目录通过静态文件服务对外暴露即可，无需专用服务器：

```

```

服务端只需记录数据集 ID 与文件目录的映射关系，前端通过 `tileset.json` URL 加载。

#### 9.3.4 可视化预览

**技术栈**：Cesium JS 或 Potree

### 10.6 实现方案

#### 前端：MapLibre GL JS

MapLibre GL JS 原生支持多图层叠加、样式动态切换，是 MVT + WMS 混合场景的最佳选择。读取服务组配置后，按 `layer_order` 顺序构建地图：

```javascript
// 读取服务组配置（含 map_config）
const group = await fetch('/api/service-groups/123').then(r => r.json());
const { map_config, services } = group;

const sources = {}, layers = [];

// 按 layer_order 顺序构建图层
for (const svcId of map_config.layer_order) {
    const svc = services[svcId];
    const cfg = map_config.layers[svcId];
    if (svc.type === 'wms') {
        sources[svcId] = {
            type: 'raster',
            tiles: [`${svc.url}?SERVICE=WMS&...&bbox={bbox-epsg-3857}`],
            tileSize: 256
        };
        layers.push({ id: svcId, type: 'raster', source: svcId, paint: { 'raster-opacity': cfg.opacity } });
    } else if (svc.type === 'mvt') {
        sources[svcId] = { type: 'vector', tiles: [svc.url] };
        // 从 SLD 转换后的 Mapbox Style 中取 paint/layout
        layers.push({ ...cfg.mapbox_style, id: svcId, source: svcId });
    }
}
```

## 十一、栅格 SLD 样式管理

### 11.1 功能说明

动态切片服务（tif/img）的样式管理，在现有矢量 SLD 样式管理基础上，新增对**栅格数据 SLD 样式**的完整 CRUD 支持。

**现有能力**：
- 矢量服务 SLD 样式绑定（已有）
- 影像波段组合（RGB 映射）、色彩拉伸、NoData 处理（已有）

**V1.5 新增**：
- 栅格 SLD 样式的创建、更新、删除
- 新增 **ColorMap（颜色表）** 样式类型：单波段影像按像素值映射颜色

典型应用场景：
- DEM 高程数据：低→高 映射为 绿→黄→红→白
- NDVI 植被指数：-1~1 映射为 棕→黄→绿
- 地表温度：冷→暖 色带渐变
- 土地利用分类图：离散值映射为固定颜色

### 11.2 栅格 SLD 与矢量 SLD 的区别

| | 矢量 SLD | 栅格 SLD |
|---|---|---|
| 控制对象 | 几何要素（点/线/面）的填充、描边 | 像素值的颜色映射 |
| 核心元素 | `PolygonSymbolizer` / `LineSymbolizer` / `PointSymbolizer` | `RasterSymbolizer` |
| 颜色表 | 不适用 | `ColorMap`：像素值 → 颜色 |
| 已有支持 | ✅ | 部分（波段/拉伸/NoData），ColorMap 待新增 |

### 11.3 ColorMap 样式说明

ColorMap 是栅格 SLD 的核心新增能力，支持两种模式：

**模式一：渐变映射（interpolate）**

像素值在断点之间线性插值颜色，适合连续数据（高程、温度、NDVI）：

```xml
<RasterSymbolizer>
  <ColorMap type="ramp">
    <ColorMapEntry color="#006837" quantity="-1.0" label="低植被" opacity="1.0"/>
    <ColorMapEntry color="#ffffcc" quantity="0.0"  label="裸地"/>
    <ColorMapEntry color="#1a9850" quantity="0.5"  label="中等植被"/>
    <ColorMapEntry color="#004529" quantity="1.0"  label="高植被"/>
  </ColorMap>
</RasterSymbolizer>
```

**模式二：离散映射（values）**

每个像素值精确匹配一个颜色，适合分类数据（土地利用、地物分类）：

```xml
<RasterSymbolizer>
  <ColorMap type="values">
    <ColorMapEntry color="#a6cee3" quantity="10" label="耕地"/>
    <ColorMapEntry color="#33a02c" quantity="20" label="林地"/>
    <ColorMapEntry color="#b2df8a" quantity="30" label="草地"/>
    <ColorMapEntry color="#1f78b4" quantity="40" label="水体"/>
    <ColorMapEntry color="#fb9a99" quantity="50" label="建设用地"/>
  </ColorMap>
</RasterSymbolizer>
```

**ColorMap 配置项**：

| 配置项 | 说明 |
|---|---|
| 类型 | ramp（渐变）/ values（离散）/ intervals（分段） |
| 断点列表 | 每个断点：像素值 + 颜色 + 标签 + 透明度 |
| 扩展模式 | 超出范围的值如何处理（使用边界色 / 透明） |

### 11.4 预置颜色表模板

参考 ColorBrewer 和遥感行业惯例，预置以下模板供用户快速选择：

| 模板名 | 类型 | 适用数据 |
|---|---|---|
| 高程（绿→黄→棕→白） | ramp | DEM、地形 |
| 植被指数（棕→黄→绿） | ramp | NDVI、EVI |
| 温度（蓝→绿→黄→红） | ramp | 地表温度、热岛 |
| 降水（白→浅蓝→深蓝） | ramp | 降水量 |
| 土地利用（定性10色） | values | 土地分类、地物分类 |
| 灰度 | ramp | 单波段通用 |

用户也可以从零手动配置断点和颜色。

### 11.5 开源实现方案

**技术栈**：GeoServer SLD REST API + Python

GeoServer 原生支持栅格 SLD，通过 REST API 管理样式：

```python
import requests

GEOSERVER_URL = "http://localhost:8080/geoserver"
AUTH = ("admin", "geoserver")

# 创建栅格 SLD 样式
def create_raster_style(style_name, sld_content):
    # 1. 创建样式条目
    requests.post(
        f"{GEOSERVER_URL}/rest/styles",
        json={"style": {"name": style_name, "filename": f"{style_name}.sld"}},
        auth=AUTH
    )
    # 2. 上传 SLD 内容
    requests.put(
        f"{GEOSERVER_URL}/rest/styles/{style_name}",
        data=sld_content,
        headers={"Content-Type": "application/vnd.ogc.sld+xml"},
        auth=AUTH
    )

# 更新样式
def update_raster_style(style_name, sld_content):
    requests.put(
        f"{GEOSERVER_URL}/rest/styles/{style_name}",
        data=sld_content,
        headers={"Content-Type": "application/vnd.ogc.sld+xml"},
        auth=AUTH
    )

# 删除样式
def delete_raster_style(style_name):
    requests.delete(
        f"{GEOSERVER_URL}/rest/styles/{style_name}?purge=true",
        auth=AUTH
    )
```

**前端 ColorMap 编辑器**：提供可视化断点编辑，用户操作后生成 SLD XML：

```javascript
// 断点配置 → SLD XML 生成
function buildColorMapSLD(entries, type = 'ramp') {
    const entryXml = entries.map(e =>
        `<ColorMapEntry color="${e.color}" quantity="${e.value}" label="${e.label}" opacity="${e.opacity ?? 1}"/>`
    ).join('\n    ');
    return `<?xml version="1.0" encoding="UTF-8"?>
<StyledLayerDescriptor version="1.0.0">
  <NamedLayer><UserStyle><FeatureTypeStyle><Rule>
    <RasterSymbolizer>
      <ColorMap type="${type}">
        ${entryXml}
      </ColorMap>
    </RasterSymbolizer>
  </Rule></FeatureTypeStyle></UserStyle></NamedLayer>
</StyledLayerDescriptor>`;
}
```

## 十一、发布四维地球日新图服务

### 11.1 背景与目标

日新图是四维地球每日更新的卫星影像产品，原有服务发布依赖"数简"软件作为中间引擎。本章调研自建日新图服务发布系统的方案，目标是完全替代"数简"，实现从原始影像到对外WMTS服务的完整发布链路，同时对现有对外API（四维云开放平台）的影响最小。

**系统定位**：我们是日新图的数据提供方，原始GeoTIFF影像存储在腾讯云COS或华为云OBS上，需要自建系统将其发布为标准WMTS服务供客户调用。

**已知约束**：
- 原始影像坐标系为 EPSG:4326，无需重投影
- 影像质检由生产部门完成，进入指定目录的影像均为合格数据，发布系统无需按条件筛选
- 现有系统已支持：定时同步、增量同步、元数据入库、同步状态管理，但不支持COS/OBS数据源
- 现有系统已支持：生成服务URL、发布WMTS服务
- 现有系统缺失：服务管理后台UI

### 11.2 整体数据流

```
生产部门处理好的影像
  → 存入 COS/OBS 指定目录
  → 同步任务发现新文件，元数据入库
  → 自动触发 COG 转换，转换结果存回 COS/OBS
  → 管理员在后台创建服务，选定影像，发布
  → WMTS 服务根据服务注册表，动态路由到对应 COG 文件
  → 客户通过四维云开放平台 API 查询并消费瓦片
```

### 11.3 核心技术选型：COG + 动态切片

原始 GeoTIFF 需要转换为 **COG（Cloud Optimized GeoTIFF）** 格式后再发布，这是整个系统最关键的架构决策。

#### 11.3.1 为什么选 COG 而非预切片

| 对比维度 | 预切片（MBTiles/XYZ） | COG 动态切片 |
|---|---|---|
| 切片时机 | 发布前离线生成 | 请求时实时读取 |
| 新影像可用时间 | 切片完成后（可能数小时） | COG 转换完成后（分钟级） |
| 存储成本 | 原始文件 + 瓦片文件，翻倍 | 仅 COG 文件，约原始大小 |
| 响应速度 | 极快（静态文件） | 快（COG 内部分块，支持范围读取） |
| 适合场景 | 影像量小、更新不频繁 | 影像量大、每日更新 |

日新图每天都有新数据，预切片的时间成本会成为发布瓶颈，**推荐 COG 路线**。

#### 11.3.2 COG 格式说明

COG 是标准 GeoTIFF 的扩展，通过内部分块（Tiling）和金字塔（Overviews）结构，支持 HTTP Range Request 按需读取局部数据，无需下载整个文件即可提取任意区域、任意层级的瓦片。

GDAL 通过 `/vsicurl/`（HTTP）、`/vsioss/`（华为云OBS）、`/vsicos/`（腾讯云COS）等虚拟文件系统，可直接读取云存储上的 COG 文件。

### 11.4 需要补齐的功能模块

#### 11.4.1 COS/OBS 数据源接入

现有同步模块不支持云存储，需要增加存储适配层。

**技术方案**：抽象统一接口，屏蔽 COS/OBS 差异：

```python
class StorageAdapter:
    def list_new_files(self, prefix: str, since: datetime) -> List[str]: ...
    def download(self, key: str, local_path: str): ...
    def upload(self, local_path: str, key: str): ...
    def get_presigned_url(self, key: str, expires_in: int) -> str: ...

class COSAdapter(StorageAdapter):
    """腾讯云 COS 实现，基于 cos-python-sdk-v5"""

class OBSAdapter(StorageAdapter):
    """华为云 OBS 实现，基于 esdk-obs-python"""
```

**同步流程**：
1. 定时任务扫描 COS/OBS 指定目录，对比本地元数据库，找出新增文件
2. 提取影像元数据（空间范围、分辨率、波段数等，通过 GDAL 读取）
3. 写入元数据库，状态标记为 `pending_cog`
4. 触发 COG 转换任务

**参考文档**：
- [腾讯云 COS Python SDK](https://cloud.tencent.com/document/product/436/12269)
- [华为云 OBS Python SDK](https://support.huaweicloud.com/sdk-python-devg-obs/obs_22_0001.html)

#### 11.4.2 COG 转换流水线

新影像入库后自动触发，将原始 GeoTIFF 转换为 COG 格式并存回云存储。

**转换命令**（EPSG:4326，无需重投影）：

```bash
# 第一步：生成内部金字塔（overview）
gdaladdo -r average input.tif 2 4 8 16 32 64 128

# 第二步：转换为 COG
gdal_translate input.tif output_cog.tif \
  -co TILED=YES \
  -co COMPRESS=DEFLATE \
  -co COPY_SRC_OVERVIEWS=YES \
  -co BLOCKXSIZE=512 \
  -co BLOCKYSIZE=512 \
  -co BIGTIFF=IF_SAFER
```

**流水线状态机**：

```
pending_cog → converting → cog_ready
                         ↘ cog_failed（可重试）
```

**数据库字段补充**：

```sql
ALTER TABLE daily_image ADD COLUMN cog_key TEXT;         -- COG 文件在云存储的路径
ALTER TABLE daily_image ADD COLUMN cog_status VARCHAR(20) DEFAULT 'pending_cog';
ALTER TABLE daily_image ADD COLUMN cog_converted_at TIMESTAMP;
```

#### 11.4.4 WMTS 动态路由（替代"数简"的核心）

推荐使用 **titiler** 作为 WMTS/XYZ 瓦片服务引擎，它原生支持读取云存储上的 COG 文件，无需自研切片逻辑。

**titiler 简介**：
- 基于 FastAPI 的开源瓦片服务器
- 通过 GDAL 虚拟文件系统直接读取 COS/OBS 上的 COG
- 支持单文件服务和多文件 Mosaic（`titiler-mosaic`）
- 支持 XYZ、WMTS 协议

**Mosaic 发布逻辑**：

```python
from cogeo_mosaic.mosaic import MosaicJSON

# 发布一个服务 = 创建一个 mosaic，包含该服务绑定的所有 COG 的访问 URL
def publish_service(service_id: int):
    images = get_service_images(service_id)  # 查 service_image 关联表
    cog_urls = [
        f"/vsioss/{img.cog_key}"   # 华为云OBS
        # 或 f"/vsicos/{img.cog_key}"  # 腾讯云COS
        for img in images
    ]
    mosaic = MosaicJSON.from_urls(cog_urls)
    save_mosaic(service_id, mosaic.dict())  # 存入数据库或文件
```

**瓦片请求路由**：

```
GET /wmts/{service_id}/{z}/{x}/{y}.png
  ↓
查询 service 表，确认 status=1（已发布）
  ↓
读取该 service_id 对应的 mosaic 配置
  ↓
titiler 根据 z/x/y 坐标，从 mosaic 中找到覆盖该瓦片的 COG
  ↓
通过 GDAL /vsioss/ 或 /vsicos/ 读取 COG 对应区域
  ↓
裁切 + 重采样 → 返回 PNG/JPEG 瓦片
```

多景影像重叠时，titiler-mosaic 默认取第一个覆盖的影像，可配置为取最新或最优。

**参考文档**：
- [titiler 官方文档](https://developmentseed.org/titiler/)
- [cogeo-mosaic](https://github.com/developmentseed/cogeo-mosaic)

```

```

## 十二、时序影像服务

### 12.1 功能说明

时序影像服务是将同一区域、不同时间的多景影像组织为一个服务，供客户端按时间轴切换查看，用于土地变化监测、工程进度跟踪、灾害前后对比等场景。

与日新图服务的核心区别：

| 维度 | 日新图服务 | 时序影像服务 |
|---|---|---|
| 核心维度 | 空间覆盖（今天哪里有图） | 时间序列（同一地方不同时间） |
| 影像关系 | 多景拼接为一张完整底图 | 多景按时间轴排列，逐帧切换 |
| 更新方式 | 每日自动追加 | 按需手动组织 |
| 客户端交互 | 普通地图图层 | 时间滑块 + 多时相切换 |

### 12.2 设计决策：基于现有服务组改造

系统已有"服务组"功能，支持将多个已发布服务打包为一个 URL 对外提供。时序影像服务在此基础上扩展，**不新建独立模块**，而是在服务组中增加时间维度支持。

**改造原则**：
- 现有普通服务组行为完全不变，向后兼容
- 新增 `group_type` 字段区分普通服务组与时序服务组
- 时序服务组的每个成员服务自动从影像元数据的"创建时间"读取 `image_time`，无需用户手动填写

### 12.3 数据库改造

仅需两处改动：

```sql
-- 1. 服务组表：新增类型字段
ALTER TABLE service_group
    ADD COLUMN group_type VARCHAR(20) DEFAULT 'normal';
    -- 'normal'   = 普通服务组（现有行为不变）
    -- 'temporal' = 时序影像服务组

-- 2. 成员关联表：新增影像时间字段
ALTER TABLE service_group_item
    ADD COLUMN image_time DATE;
    -- 添加服务时由后端自动从服务元数据的"创建时间"读取并写入
    -- 普通服务组此字段为 NULL，不影响现有逻辑
```

### 12.4 后端改造

#### 12.4.1 添加服务时自动写入 image_time

将服务添加到 `group_type=temporal` 的服务组时，后端自动从该服务的元数据中读取"创建时间"，写入 `service_group_item.image_time`，无需前端传入。

#### 12.4.2 坐标系一致性校验

时序服务组内各服务的网格集（坐标系）必须一致，否则前端切换时相时地图会出现偏移。

**校验逻辑**：添加服务到时序服务组时，后端检查待添加服务的网格集是否与组内已有服务一致：

```python
def add_service_to_temporal_group(group_id: int, service_id: int):
    group = get_group(group_id)
    if group.group_type != 'temporal':
        # 普通服务组，跳过校验
        return add_item(group_id, service_id)

    new_service = get_service(service_id)
    existing_items = get_group_items(group_id)

    if existing_items:
        existing_crs = existing_items[0].crs  # 取组内第一个服务的坐标系
        if new_service.crs != existing_crs:
            raise ValidationError(
                f"坐标系不一致：组内服务使用 {existing_crs}，"
                f"待添加服务使用 {new_service.crs}，请统一后再添加"
            )

    add_item(group_id, service_id, image_time=new_service.created_time)
```

**校验时机**：添加服务时实时校验，不通过则返回错误提示，阻止添加。

#### 12.4.3 新增 timeline 接口

现有服务组接口返回服务列表，时序服务组额外提供一个按时间排序的 timeline 接口，供前端时间滑块使用：

```
GET /api/service-group/{id}/timeline

响应（按 image_time 升序）：
{
  "group_id": "xxx",
  "group_type": "temporal",
  "items": [
    {
      "image_time": "2024-01-01",
      "service_name": "区域A-2024年1月",
      "service_url": "https://...",
      "thumbnail": "https://..."
    },
    {
      "image_time": "2024-02-01",
      "service_name": "区域A-2024年2月",
      "service_url": "https://...",
      "thumbnail": "https://..."
    }
  ]
}
```

#### 12.4.4 现有服务列表接口调整

`group_type=temporal` 的服务组，返回成员列表时按 `image_time` 升序排列（现有普通服务组按添加顺序，行为不变）。

### 12.5 前端管理后台改造

对照现有服务组详情页，改动集中在以下位置：

| 位置 | 现有 | 改造后 |
|---|---|---|
| 基础属性区 | 名称、描述、资产标签 | 新增"服务组类型"选择（普通 / 时序） |
| 成员列表列 | 服务名称、格式、网格集、层级、缩略图、资产标签 | 时序类型额外显示"影像时间"列 |
| 成员列表排序 | 添加顺序 | 时序类型按影像时间升序排列 |
| 添加服务 | 无校验 | 时序类型添加时，坐标系不一致给出错误提示 |

添加服务弹窗本身无需改动，时间由后端自动写入，用户无感知。

